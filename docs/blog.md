# Сервис блога

## Назначение

Сервис `blog` отвечает за работу с тегами и статьями блога. HTTP-доступ к нему предоставляется через API Gateway контроллерами из библиотеки `gateway-controllers`:

- `TagController` — теги блога
- `ArticleController` — статьи блога

Все HTTP-маршруты используют глобальный префикс `/api`. Swagger-документация доступна по адресу `localhost:3000/api/docs`, контроллеры сгруппированы по тегам `BLOG / Tag` и `BLOG / Article`.

Сервис использует собственную базу данных PostgreSQL, Redis для кэширования и RabbitMQ для интеграции с auth-, profile- и log-сервисами.

## Реализованный функционал

- Теги блога:
  - пагинированный список с поиском по названию
  - детальная информация по тегу с привязанными статьями
  - создание и удаление тегов администратором
- Статьи блога:
  - публичный пагинированный список опубликованных статей
  - список статей текущего автора с любыми статусами
  - публичный просмотр статьи по slug
  - просмотр собственной статьи по slug, включая неопубликованные
  - создание, публикация, снятие с публикации, обновление и удаление статей
  - фильтрация по поиску, автору, датам и тегам
- Поддержка анонимных статей: при `isAnonim = true` статья сразу публикуется и не привязывается к автору
- Автоматическая генерация slug из названия тега или статьи
- Кэширование точечных запросов тегов и статей в Redis с инвалидацией при изменении
- Синхронизация снимка пользователя (`UserSnapshot`) через RabbitMQ-события auth- и profile-сервисов
- Публикация audit-событий в log-сервис через RabbitMQ
- Полная типизация запросов и ответов в соответствии с gRPC-схемой и HTTP-схемой
- Единая валидация DTO через `class-validator`

## Маршрутизация

| Группа   | Базовый путь       | Swagger-тег      |
| -------- | ------------------ | ---------------- |
| Теги     | `/api/blog/tag`    | `BLOG / Tag`     |
| Статьи   | `/api/blog/article` | `BLOG / Article` |

Списочные методы используют HTTP-метод `QUERY` и принимают параметры пагинации в теле запроса, а не в query string.

## Авторизация и роли

- **—** — публичный метод, авторизация не требуется
- **ADMIN** — требуется валидный access-токен пользователя с ролью администратора

Для защищённых методов передаётся заголовок:

```http
Authorization: Bearer <accessToken>
```

`ValidateInputParam` извлекает access-токен из заголовка `Authorization`, а данные сессии — из параметров HTTP-запроса и `User-Agent`. При отсутствии или невалидности токена возвращается `401`, при недостатке прав — `403`.

На уровне gRPC-сервиса дополнительно проверяется владелец статьи: администратор может редактировать, публиковать и снимать с публикации только собственные статьи. Просматривать неопубликованные статьи через `GetMyArticleBySlug` также может только автор.

## Теги блога

### Методы

| HTTP   | Путь                  | gRPC-метод       | Роли  | Назначение                                     |
| ------ | --------------------- | ---------------- | ----- | ---------------------------------------------- |
| QUERY  | `/api/blog/tag`       | `GetPaginatedTags` | —     | Пагинированный список тегов с поиском          |
| GET    | `/api/blog/tag/:slug` | `GetTagBySlug`     | —     | Детальная информация о теге и его статьях      |
| POST   | `/api/blog/tag`       | `CreateTag`        | ADMIN | Создание тега                                  |
| DELETE | `/api/blog/tag/:slug` | `DeleteTag`        | ADMIN | Удаление тега                                  |

### Параметры и тело запроса

**Пагинация тегов**

| Поле     | Тип    | Обязательно | Ограничения                      |
| -------- | ------ | ----------- | -------------------------------- |
| `page`   | number | нет         | целое число от 1, по умолчанию 1 |
| `limit`  | number | нет         | целое число от 1, по умолчанию 10 |
| `search` | string | нет         | длина от 3 до 90 символов        |

**Создание тега**

| Поле   | Тип    | Обязательно | Ограничения               |
| ------ | ------ | ----------- | ------------------------- |
| `name` | string | да          | длина от 2 до 90 символов |

Slug тега генерируется автоматически из `name`. Если тег с таким slug уже существует, возвращается `409 Conflict`. `slug` тега передаётся в path-параметре для методов просмотра и удаления.

При удалении тег исчезает из всех связанных статей, сами статьи при этом не удаляются.

## Статьи блога

### Методы

| HTTP   | Путь                                | gRPC-метод           | Роли  | Назначение                                                       |
| ------ | ----------------------------------- | -------------------- | ----- | ---------------------------------------------------------------- |
| QUERY  | `/api/blog/article/public`          | `GetArticles`        | —     | Публичный список опубликованных статей                            |
| QUERY  | `/api/blog/article/me`              | `GetMyArticles`      | ADMIN | Список статей текущего автора с любыми статусами                  |
| GET    | `/api/blog/article/public/:slug`    | `GetArticleBySlug`   | —     | Публичный просмотр опубликованной статьи по slug                  |
| GET    | `/api/blog/article/me/:slug`        | `GetMyArticleBySlug` | ADMIN | Просмотр собственной статьи по slug, включая неопубликованные     |
| POST   | `/api/blog/article`                 | `CreateArticle`      | ADMIN | Создание статьи                                                   |
| PATCH  | `/api/blog/article/:slug/publish`   | `PublishArticle`     | ADMIN | Публикация статьи                                                 |
| PATCH  | `/api/blog/article/:slug/unpublish` | `UnpublishArticle`   | ADMIN | Снятие статьи с публикации                                        |
| PUT    | `/api/blog/article/:slug`           | `UpdateArticle`      | ADMIN | Обновление статьи                                                 |
| DELETE | `/api/blog/article/:slug`           | `DeleteArticle`      | ADMIN | Удаление статьи                                                   |

### Тело запроса для списков

| Поле             | Тип       | Обязательно | Описание                                      |
| ---------------- | --------- | ----------- | --------------------------------------------- |
| `page`           | number    | нет         | Страница, от 1, по умолчанию 1                |
| `limit`          | number    | нет         | Количество на странице, от 1, по умолчанию 10 |
| `search`         | string    | нет         | Поиск, длина от 3 до 90 символов              |
| `authorNickname` | string    | нет         | Никнейм автора, длина от 3 до 80 символов     |
| `dateFrom`       | date-time | нет         | Начало диапазона дат создания статей          |
| `dateTo`         | date-time | нет         | Конец диапазона дат создания статей           |
| `tags`           | string[]  | нет         | От 1 до 20 уникальных slug тегов              |

Даты не могут быть в будущем. Публичный список всегда возвращает только опубликованные статьи, даже если фильтры не заданы.

### Создание статьи

| Поле        | Тип     | Обязательно | Ограничения                          |
| ----------- | ------- | ----------- | ------------------------------------ |
| `name`      | string  | да          | длина от 2 до 90 символов            |
| `shortDesc` | string  | да          | длина от 1 до 200 символов           |
| `content`   | string  | да          | длина от 300 до 3000 символов        |
| `tags`      | string[] | да         | от 1 до 20 уникальных slug тегов     |
| `isAnonim`  | boolean | да          | признак анонимной статьи             |

Правила создания:

- slug статьи генерируется автоматически из `name`;
- если статья с таким slug уже существует, возвращается `409 Conflict`;
- если хотя бы один тег не найден, возвращается `400 Bad Request`;
- при `isAnonim = true` статья создаётся сразу опубликованной (`isPublished = true`) без автора;
- при `isAnonim = false` статья создаётся неопубликованной (`isPublished = false`) и привязывается к текущему администратору.

### Обновление статьи

| Поле        | Тип      | Обязательно | Ограничения                     |
| ----------- | -------- | ----------- | ------------------------------- |
| `shortDesc` | string   | нет         | длина от 1 до 200 символов      |
| `content`   | string   | нет         | длина от 300 до 3000 символов   |
| `tags`      | string[] | нет         | от 1 до 20 уникальных slug тегов |

`slug` статьи передаётся в path-параметре. После успешного обновления статья помечается флагом `isUpdated = true`. Если передан несуществующий тег, возвращается `400 Bad Request`.

### Публикация и снятие с публикации

- Публикация переводит статью в `isPublished = true`.
- Снятие с публикации переводит статью в `isPublished = false`.
- Если статья уже находится в запрашиваемом статусе, возвращается `409 Conflict`.
- Управлять статусом может только автор статьи.

### Удаление статьи

- Неопубликованную статью может удалить только её автор.
- Опубликованную статью может удалить любой администратор.
- Перед удалением статья должна существовать, иначе возвращается `404 Not Found`.

## Форматы ответов

- Список тегов: `pagination` и массив `tags` с полями `slug`, `name`.
- Детальная информация о теге: `slug`, `name`, `articles`, `createdAt`, `updatedAt`.
- Статья в списке тега: `slug`, `name`, `shortDesc`, `authorNickname`, `authorAvatarId`.
- Созданный/удалённый тег: `slug`, `name`, `createdAt`, `updatedAt` (для удаления — пустой объект).
- Список статей: `pagination` и массив `articles` с полями `slug`, `name`, `shortDesc`, `authorNickname`, `authorAvatarId`, `isPublished`.
- Статья по slug: `name`, `slug`, `shortDesc`, `content`, `authorId`, `authorNickname`, `authorAvatarId`, `tags`, `isPublished`, `isUpdated`, `createdAt`, `updatedAt`.
- Пагинация: `page`, `limit`, `total`, `totalPages`, `hasNext`, `hasPrev`, а также переданные фильтры `search`, `authorNickname`, `dateFrom`, `dateTo`, `tags`.

## Кэширование

Сервис кэширует точечные запросы в Redis:

| Данные            | Ключ                  | TTL по умолчанию | Инвалидация                          |
| ----------------- | --------------------- | ---------------- | ------------------------------------ |
| Тег по slug       | `blog-tag:<slug>`     | 300 секунд       | удаление тега                        |
| Статья по slug    | `blog-article:<slug>` | 300 секунд       | публикация, обновление и удаление    |

TTL настраивается переменными `TAVERN_BLOG_TAG_CACHE_TTL` и `TAVERN_BLOG_ARTICLE_CACHE_TTL`. При отсутствии значения в кэше данные читаются из PostgreSQL и результат записывается обратно в Redis.

## Интеграция с blog-сервисом

`GatewayControllersModule` регистрирует gRPC-клиент `BLOG_CLIENT`:

- пакет: `blog`
- proto-файл: `proto/blog.proto`
- адрес сервиса: переменная окружения `TAVERN_BLOG_GRPC_URL`, по умолчанию `blog-service:5000`
- используемые gRPC-сервисы: `TagService`, `ArticleService`

Gateway добавляет к gRPC-запросу `ValidateInput` (access-токен и данные сессии) для защищённых методов и вызывает соответствующий gRPC-метод. Ответы маппятся в HTTP-формат.

## RabbitMQ

### Входящие события

Сервис поддерживает снимок пользователя для отображения автора статьи и фильтрации по никнейму.

| Событие                   | Источник | Обработка                                             |
| ------------------------- | -------- | ----------------------------------------------------- |
| `user.registered`         | auth     | создание `UserSnapshot`                               |
| `user.deleted`            | auth     | удаление `UserSnapshot`                               |
| `profile.update`          | profile  | обновление никнейма в `UserSnapshot`                  |

### Исходящие события

Все действия с тегами и статьями публикуются в очередь `log`:

| Событие                   | Данные                                  |
| ------------------------- | --------------------------------------- |
| `blog.tag.create`         | `adminId`, `tagSlug`                    |
| `blog.tag.delete`         | `adminId`, `tagSlug`                    |
| `blog.article.create`     | `authorId`, `slug`, `isAnonim`          |
| `blog.article.publish`    | `authorId`, `slug`, `status`            |
| `blog.article.unpublish`  | `authorId`, `slug`, `status`            |
| `blog.article.update`     | `authorId`, `slug`                      |
| `blog.article.delete`     | `adminId`, `slug`                       |

## Модели базы данных

| Модель         | Назначение                                                        |
| -------------- | ----------------------------------------------------------------- |
| `UserSnapshot` | Снимок пользователя: `userId`, `nickname`, `avatarId`             |
| `Tag`          | Тег блога: `name`, уникальный `slug`                              |
| `Article`      | Статья: `name`, `slug`, `shortDesc`, `content`, автор, теги, статусы |

Связь статей и тегов — many-to-many через таблицу `tags_to_articles`. При удалении пользователя автор статьи становится `null`, сама статья сохраняется.

## ENV-переменные

- **TAVERN_BLOG_GRPC_PORT** — порт gRPC-сервера (по умолчанию 5000; в `.env.example` — 5001)
- **TAVERN_BLOG_DB_URL** — ссылка на базу данных blog-сервиса
- **TAVERN_AUTH_DB_URL** — ссылка на базу данных auth-сервиса для валидации токенов
- **TAVERN_JWT_SECRET** — JWT-секрет для проверки access-токенов
- **TAVERN_JWT_ACCESS_TOKEN_TTL** — время жизни access-токена в минутах
- **TAVERN_JWT_REFRESH_TOKEN_TTL** — время жизни refresh-токена в днях
- **TAVERN_RMQ_USER** — пользователь RabbitMQ
- **TAVERN_RMQ_PASSWORD** — пароль RabbitMQ
- **TAVERN_RMQ_URL** — URL RabbitMQ
- **TAVERN_REDIS_URL** — URL Redis
- **TAVERN_REDIS_PASSWORD** — пароль Redis
- **TAVERN_BLOG_TAG_CACHE_TTL** — TTL кэша тега в секундах (по умолчанию 300)
- **TAVERN_BLOG_ARTICLE_CACHE_TTL** — TTL кэша статьи в секундах (по умолчанию 300)

## ENV-переменные Gateway

- **TAVERN_BLOG_GRPC_URL** — адрес blog-сервиса для gRPC
- **TAVERN_JWT_SECRET** — JWT-секрет для проверки access-токенов
- **TAVERN_GATEWAY_HTTP_PORT** — порт HTTP Gateway (по умолчанию 3000)
