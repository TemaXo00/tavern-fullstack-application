# Сервис мероприятий

## Назначение

Сервис `event` отвечает за работу с мероприятиями, тегами и участниками. HTTP-доступ к нему предоставляется через API Gateway контроллерами из библиотеки `gateway-controllers`:

- `TagController` — теги мероприятий
- `EventController` — мероприятия
- `ParticipantController` — участие в мероприятиях

Все HTTP-маршруты используют глобальный префикс `/api`. Swagger-документация доступна по адресу `localhost:3000/api/docs`, контроллеры сгруппированы по тегам `EVENT / Tag`, `EVENT / Event` и `EVENT / Participant`.

## Реализованный функционал

- Теги мероприятий:
  - пагинированный список с поиском
  - детальная информация по тегу с ближайшими событиями
  - создание, обновление и удаление тегов администратором
- Мероприятия:
  - публичные и приватные списки с фильтрацией
  - список мероприятий текущего организатора
  - публичные и приватные мероприятия конкретного пользователя
  - публичный, приватный и собственный просмотр мероприятия по slug
  - создание мероприятия в статусе `DRAFT`
  - публикация, отмена и завершение мероприятия
  - открытие/закрытие записи участников
  - передача мероприятия другому организатору
  - редактирование и удаление мероприятия
- Участники:
  - список мероприятий, в которых участвует пользователь
  - список участников мероприятия
  - вступление в мероприятие и выход из него
  - добавление пользователя организатором
  - изменение статуса участника
  - удаление участника организатором
- Единая валидация DTO через `class-validator`
- Преобразование строковых enum из HTTP/DTO в числовые значения gRPC и обратно
- Проверка access-токена и ролей на уровне Gateway; проверка владельца мероприятия — на уровне event-сервиса

## Маршрутизация

| Группа      | Базовый путь            | Swagger-тег        |
| ----------- | ----------------------- | ------------------ |
| Теги        | `/api/event/tag`        | `EVENT / Tag`      |
| Мероприятия | `/api/event/event`      | `EVENT / Event`    |
| Участники   | `/api/event/participant` | `EVENT / Participant` |

Списочные методы используют HTTP-метод `QUERY` и принимают параметры пагинации в теле запроса, а не в query string.

## Авторизация и роли

- **—** — публичный метод, авторизация не требуется
- **Auth** — требуется валидный access-токен любого зарегистрированного пользователя
- **ADMIN**, **MODERATOR** — требуются соответствующие роли
- **Организатор** — дополнительная проверка владельца мероприятия в event-сервисе

Для защищённых методов передаётся заголовок:

```http
Authorization: Bearer <accessToken>
```

`ValidateInputParam` извлекает access-токен из заголовка `Authorization`, а данные сессии — из параметров HTTP-запроса и `User-Agent`. При отсутствии или невалидности токена возвращается `401`, при недостатке прав — `403`.

## Статусы

### Статусы мероприятия

| Статус      | Значение                        |
| ----------- | ------------------------------- |
| `DRAFT`     | Черновик                        |
| `PUBLISHED` | Опубликовано                    |
| `CANCELLED` | Отменено                        |
| `FINISHED`  | Завершено                       |

### Статусы участника

| Статус     | Значение                    |
| ---------- | --------------------------- |
| `WAITLIST` | Лист ожидания               |
| `RECORDED` | Записан на мероприятие      |
| `FIXED`    | Участие подтверждено        |
| `NOT_COME` | Не пришёл на мероприятие    |

Gateway возвращает статусы строками (`DRAFT`, `PUBLISHED`, `RECORDED` и т.д.), хотя внутри gRPC используются числовые значения. Преобразование выполняет `EventGatewayMapService`.

## Логика участия

- При вступлении в мероприятие:
  - если есть свободные места, пользователь получает статус `RECORDED`;
  - если свободных мест нет, пользователь попадает в `WAITLIST`.
- При выходе из мероприятия:
  - участник из `WAITLIST` просто удаляется из листа ожидания;
  - при выходе участника из основного списка его место передаётся первому участнику из `WAITLIST`.
- Изменение статуса участника зависит от статуса мероприятия:
  - `FINISHED` — доступны `FIXED` и `NOT_COME`;
  - `PUBLISHED` — доступны `WAITLIST` и `RECORDED`;
  - `DRAFT` и `CANCELLED` — изменение статуса запрещено.

## Форматы ответов

- Списки мероприятий: `pagination` и массив `events`.
- Список участников мероприятия: `event`, `pagination` и массив `participants`.
- Мероприятия пользователя: `participant`, `pagination` и массив `events`.
- Детальная информация о мероприятии: `slug`, `name`, `description`, `dateAndTime`, `totalPlaces`, `leftPlaces`, `waitingUsers`, `isJoinBlocked`, `status`, `tags`, `organizerId`, `organizer`, `participants`, `createdAt`.
- Результат методов изменения мероприятия: `slug`, `name`, `description`, `dateAndTime`, `totalPlaces`, `leftPlaces`, `waitingUsers`, `isJoinBlocked`, `status`, `organizerId`.
- Участник: `nickname`, `eventId`, `avatarId`, `isFixed`, `note`, `status`.
- Тег: `slug`, `name`, `description`, `color`, `createdAt`, `updatedAt`; детальный ответ дополнительно содержит `events`.

## Интеграция с event-сервисом

`GatewayControllersModule` регистрирует gRPC-клиент `EVENT_CLIENT`:

- пакет: `event`
- proto-файл: `proto/event.proto`
- адрес сервиса: переменная окружения `TAVERN_EVENT_GRPC_URL`, по умолчанию `event-service:5000`
- используемые gRPC-сервисы: `TagService`, `EventService`, `ParticipantService`

Gateway добавляет к gRPC-запросу `ValidateInput` (access-токен и данные сессии) и вызывает соответствующий gRPC-метод. Ответы маппятся в HTTP-формат, а числовые статусы gRPC преобразуются в строковые значения enum.

## ENV-переменные Gateway

- **TAVERN_EVENT_GRPC_URL** — адрес event-сервиса для gRPC
- **TAVERN_JWT_SECRET** — JWT-секрет для проверки access-токенов
- **TAVERN_GATEWAY_PORT** — порт HTTP Gateway (по умолчанию 3000)
